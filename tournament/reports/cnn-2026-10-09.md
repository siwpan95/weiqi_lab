## 4. 模型与训练配置

| 项 | 9 路 | 19 路 |
|---|---|---|
| 架构 | conv3×3(C=32)→ReLU→conv3×3(C=32)→ReLU→conv1×1(1) | 同左 |
| 输入 | 6×9×9 uint8 | 6×19×19 uint8 |
| 输出 | 每点一个 logit（9×9=81，掩码 softmax） | 每点一个 logit（19×19=361） |
| 损失 | 掩码 softmax 交叉熵（仅空点归一化） | 同左 |
| 优化器 | Adam（lr 2e-3，β=(0.9,0.999)），batch 64 | Adam（lr 2e-3），**batch 128** |
| 步数 | 800 | 2000 |
| 参数量 | ≈ 2.0 万 | ≈ 2.0 万（同架构，输入通道相同） |
| 权重初始化 | He 正态（seed 0） | 同左 |
| 耗时 | **83.4 s** | **1982.3 s（33.1 min）** |

实现要点：`conv` 用 **im2col + numpy matmul（BLAS）**；反向用 `col2im` 的 9 次切片累加（避开慢速 `np.add.at`）；全程 float32。
实测 19 路 **batch 128 比 batch 64 快约 3×/样本**（BLAS 大矩阵效率），故 19 路选 128。

## 6. 对比口径（保证公平）

`ml/eval_compare.py` 强制两侧完全同口径：

1. **同一语料、同一按局划分**（后 20% 局留出，与 `tools/train_markov.mjs` 一致）；
2. **同一批留出样本**：由 Python 统一复演生成，并断言 JS 侧样本顺序/目标序列一致（`assert val_next == ...`）；
3. **同一坐标口径**：引擎格式顶点，y 自下而上；
4. **同一合法性屏蔽**：两个模型都只从**空点**里选（占用点屏蔽）。为对齐旧报告，额外给出 Markov 的「不屏蔽」legacy 数值。

Markov 侧由 `node ml/export_markov.mjs`（内部 `import { PatternPolicy } from "../tools/markov.mjs"`）在**同一批样本**上产出
（样本以「最后一手 3×3 邻域 9 格棋色」传递，避免两套规则实现漂移；PatternPolicy 的签名只读该邻域，等价重建）。

## 10. 诚实结论

### 10.1 结果是否可信
- **反向正确**：方向导数自检 PASS；
- **口径对齐**：Markov 不屏蔽口径在 9 路复现 **4.13% ≈ 旧报告 4.1%**，说明对比管线没有偷换口径；
- **两面证据一致**：同一套代码，弱语料（9 路自对弈）17.58%、强语料（19 路人类）25.84% ——
  **模型不是瓶颈，语料质量才是**（这正是 `docs/TIER3_LEARNING.md` 的预判，本轮被独立验证）。

### 10.2 CNN vs 模式模型
- 19 路：**top-1 25.84% vs 11.42%（2.26×）**，**top-3 42.54% vs 27.03%（1.57×）**；两者都远超均匀基线（0.41%）。
- 9 路：**top-1 17.58% vs 8.41%（2.09×）**。
- 结论：**在两种语料上，CNN 都稳定且明显地优于模式查表模型**；差距不因语料从弱（自对弈）变强（人类）而消失（2.1×→2.3×）。

### 10.3 代价与局限（不含糊）
- **速度**：纯 numpy CPU 推理 **404.85 µs/手**，比 Markov 哈希查表慢约 **22×**，且随棋盘/通道线性放大。
  若要接入 MCTS / 循环赛，需批量化或上 GPU/torch（那将是更大的依赖破例）。
- **规模小**：网络仅 ~2 万参数、单一策略头、无价值头、无气数/征子等显式特征；
  25.84% 的 top-1 与「小策略网 + 12 万样本」的经验量级相符（对比：AlphaGo 原始策略网用 ~3000 万样本 + 大网达 ~57%）。
  即**这是起点，不是上限**。
- **平台已现**：19 路 1200 步后 val 指标进入平台（±1%），说明当前容量/数据下继续叠加步数收益有限。

### 10.4 是否值得继续投入 CNN 路线 —— **建议继续（有条件）**

**值得，依据：**
1. **学习信号真实且大**：在真实人类棋谱上把 top-1 从「查表 11%」推到「CNN 26%」，把 top-3 推到 42.5%；
   即便不追求棋力，这样的策略头对 **MCTS 先验 / 走子排序 / 开局库** 已有实用价值；
2. **可扩展性清晰**：当前是「小网 + 小数据」的结果，收益尚未饱和于更大网络/更多语料（平台来自数据量而非训练不足）；
3. **成本可移植**：`ml/` 已隔离，零依赖传统未被破坏——引擎与 `tools/` 依旧零依赖。

**推进的前置/建议（按优先级）：**
1. **扩语料**：`spec/games/human-2026-10-09.jsonl` 已有 6000 局，本轮只用了 600 局（受纯 numpy 算力限制）；
   换 GPU/torch 后可全量训练并把网络放大（≥ 6–10 层、128+ 通道）；
2. **加价值头**（AlphaZero 式双头），才能进入自对弈强化与 MCTS 集成；
3. **先做「是否上 GPU 依赖」的决策**：若目标是**棋力**，CPU 纯 numpy 不现实（22× 慢 + 无法训练大网）；
   若目标是**研究与教学演示**，当前 CPU/纯 numpy 方案已足够，应保持零依赖。

**若继续，建议的下一步实验（可量化）**：全量 6000 局 + 更大网络 + 价值头，重跑同一套 `eval_compare.py`，
对比本文的 25.84% / 42.54% 作为进度基准；并把「策略头 + MCTS」接入循环赛做 A/B（对照现有关闭搜索的基线）。
